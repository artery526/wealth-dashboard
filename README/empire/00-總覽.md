# Empire 維護文件總覽

> 文件狀態：目前版骨架
>
> 最後整理：2026-08-15

## 這套文件的用途

這套文件用來記錄 Empire 網頁系統各區塊的功能、資料來源、程式位置、排程、依賴關係與維修注意事項。

目標是讓日後維修、換電腦或重新安裝 Codex 時，可以先讀取必要的區塊文件，不必一次載入整份專案資料。

## 閱讀順序

一般維修建議依照以下順序閱讀：

1. 本文件：確認文件規則與系統範圍。
2. [系統地圖](./01-系統地圖.md)：確認前端、後端、試算表、外部服務與發布流程。
3. 目標區塊的 `README.md`：確認該區塊的入口、子頁面與依賴。
4. 目標頁面或功能的詳細文件：確認函式、API、儲存格、公式與維修流程。
5. [排程文件](./operations/排程.md)：確認是否涉及每日或定時工作。此文件尚未建立。

## 文件規則

- 一個主要功能區塊一個資料夾，例如 `blocks/財政/`、`blocks/行事曆/`。
- 區塊的 `README.md` 只做入口與依賴地圖；細節放在子文件。
- 文件記錄來源位置、函式名稱、API action、試算表分頁、範圍、公式規則與驗證方式，不複製整份程式碼。
- 每個區塊都要標示前端來源、後端來源、資料來源、排程、快取與外部依賴。
- 未確認的資訊標示為「待驗證」，不可當成已完成的功能說明。
- 機密資料只記錄設定名稱或安全存放位置，不記錄 token、密碼、`.env` 內容或 SSH key。
- 修改程式、試算表或部署設定後，應同步更新相關區塊的文件與最後驗證日期。

## 驗證原則

文件中的「已驗證」至少要能對應到一項實際證據：

- 前端：確認 `D:\wealth-dashboard\index.html` 的來源程式與正式網站行為。
- Apps Script：分開確認正式部署的 GET 與寫入型 POST/API 行為。
- Google Sheets：確認實際分頁、範圍、公式與顯示結果。
- NAS / ArkOS：確認服務重啟後的 API 或檔案實際可讀取。
- 排程：確認觸發器設定與實際執行結果，不只依照程式碼推測。
