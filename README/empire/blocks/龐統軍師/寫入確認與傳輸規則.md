# 寫入、確認與傳輸規則

## 寫入分類

| 使用者意圖 | 前端流程 | 最終 API |
| --- | --- | --- |
| 支出 | 快速支出表單直接送出，不經 AI 口令解析 | `expense` |
| 收入／已入帳配息 | 解析並組合收入欄位 | `income` |
| 轉帳／提款 | 組合來源、目的與金額 | `transfer` |
| 股票買入 | 先顯示標的、股數、金額，再確認 | `transfer` + 股票欄位 |
| 股票賣出 | 先顯示標的、股數、金額，再確認 | `transfer` + 股票欄位 |
| 配息備忘 | 先試算持股數、稅率、匯率與台幣，再確認 | `advisorDividendMemo` |

## 寫入防線

- `advisorAIRequireWrite()` 先確認 API URL 與 WRITE_TOKEN。
- Apps Script `doPost(e)` 會呼叫 `verifyWriteToken(body)`；所有授權 action 都要通過 token。
- `advisorAiParse` 與 `advisorDividendMemo` 使用 JSON POST，必要時可依前端規則 fallback 為 GET。
- 一般財務寫入會使財政快取失效；配息寫入後會使配息中心重新整理，龐統配息記錄表單也會強制重新載入持股數與匯率資料。
- 配息備忘的 `preview=1` 只試算，不應寫入；只有使用者按「確認記錄」才送正式寫入。

## 逾時處理

前端對財務寫入通常使用 45 秒等待時間。若 POST 已送出但回應逾時，畫面會提示先查詢最近紀錄，避免重複送出。

標準回查順序：

1. 查詢最近交易／收入／支出資料。
2. 確認試算表是否已有相同日期、帳戶、金額與備註。
3. 確認無寫入後才考慮重試。

## 特別注意

- `dividend` 是已入帳金額；`advisorDividendMemo` 是每股配息試算／備忘，兩者不可混用。
- 支出目前不走 AI 口令，使用龐統快速支出列或內政快速記帳；不要為支出新增自然語句訓練案例，避免與配息入帳命令混淆。
- 股票買賣同時涉及帳戶轉移與持股欄位，不能只確認帳戶餘額。
- 軍師不能繞過使用者確認刪除或撤銷既有紀錄；撤銷流程應使用專用 action 並另行回查。
- 不要因為 GET fallback 成功就當作所有 POST 行為都已驗證；正式 GET、POST 與資料回查要分開留下證據。
