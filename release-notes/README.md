# 跨討論串更新紀錄

這是網站各板塊與 Windows 帝國指揮所共用的變更紀錄來源。開始修改前，先查看 `entries/` 中相同板塊的近期紀錄與尚未發布項目，避免重複實作或漏掉既有決策。

## 每項變更一個檔案

在 `entries/` 新增一個 JSON 檔，檔名使用 `YYYY-MM-DD-簡短英文識別字.json`。不要多人共同追加同一份總清單，以降低並行討論串的合併衝突。

```json
{
  "id": "2026-10-18-finance-monthly-cashflow",
  "status": "in_progress",
  "date": null,
  "area": "財政",
  "summary": "新增國庫現況的本月收入支出資訊",
  "details": "簡述對使用者可見的變更；不要寫入帳務金額、Token 或個人資料。",
  "platforms": ["website", "windows"]
}
```

`status` 可用 `planned`、`in_progress`、`released`。未完成或尚未正式發布的紀錄保留在資料夾供其他討論串參考，但不會出現在使用者的監控面板。只有完成檢查並確認實際發布後，才把狀態改成 `released`，並將 `date` 設為實際可用日期（`YYYY-MM-DD`）。若網站與桌面版分開發布，請在 `platforms` 明確列出已上線的平台；兩端皆發布後才列兩端。

## 面板清單

GitHub Pages 工作流程會驗證所有條目，將已發布紀錄依日期由新到舊產生根目錄 `release-notes.json`。這是建置輸出，不要手動編輯或提交。Windows 監控面板按下「更新紀錄」分頁時才會讀取該靜態清單，不會讀取試算表。

每筆摘要應短而具體，例如：`10/10　財政板塊新增國庫現況的本月支出收入`。詳情保持在一至兩句，按板塊與平台標記。不可記錄私人訂單內容、財務明細、憑證或 API 金鑰。
